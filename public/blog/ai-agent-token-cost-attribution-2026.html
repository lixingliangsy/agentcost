Token cost attribution for AI agents

Token cost attribution is the practice of assigning every unit of model spend to the agent, feature and end user that caused it. Until you can attribute spend, you cannot cap it — a budget without attribution is a number you discover you have already exceeded.

Key takeaways

  • Track input and output tokens separately; they are priced differently, and output usually costs more per token.
  • A growing context window means earlier turns are re-sent on every new call — the cost repeats rather than happening once.
  • Attribution is a prerequisite for budgets: per-agent caps need per-agent numbers.

What to attribute

  1. Which agent ran. A router that fans out to three agents should not produce one undifferentiated bill.
  2. Which feature triggered it. The same agent called by different features has a different return.
  3. Which end user. One account can quietly dominate a shared budget.
  4. Which model and which call. Retries, fallbacks and streaming each change the arithmetic.

Where agent spend hides

  • Loops. An agent that retries or re-plans can multiply a cheap task many times over.
  • Context growth. Long conversations re-send earlier tokens on every turn.
  • Silent fallbacks. A fallback to a larger model changes the unit price mid-run.
  • Tool output. Large tool results get fed back in as input tokens.

Frequently asked questions

Why is attribution needed before budgeting?

A single account-level cap tells you that you overspent, not which agent did it. Per-agent caps need per-agent attribution.

Does attribution reduce the bill?

No. It shows you where the money goes. The reduction comes from the changes you make afterwards.

What about cached or discounted tokens?

They change the unit price. Record which pricing applied per call so the ledger matches the invoice.

How do we catch a runaway loop?

Alert on rate of change and on per-run cost, not only on the monthly total. A loop is only visible in the first few minutes.

Do we need to instrument every call ourselves?

Something has to emit the per-call record. CostLens consumes those records and attributes them; it cannot invent them.

Is this FinOps-certified?

No. It follows FinOps framing for attribution and budgeting but is not a certification of any kind.
